# Headroom Probe — Design Spec

**Date:** 2026-07-17 · **Owner:** Xinyuan Liu · **Target:** ICRA 2027 (~Sept 2026), sim-core + G1 preliminary
**Status:** design approved, pre-implementation.

Related: `INFLUENCE_REPORT.md`, `VALUE_INFLUENCE_POSTMORTEM.md`, `INFLUENCE_IMPROVEMENT_ROADMAP.md`, `../main (1).tex`.

---

## 1. The one decision this resolves

Does adding **genuinely-new** (GR00T-generated, *not* pool-selected) demonstrations to a diagnosed
weak region improve **net** success — and does the gain track **learnability** (middle-difficulty
regions) rather than **raw failure** (the hardest regions)?

- **YES (Middle arm has headroom, ranks above Hard and Random)** → the learnability-driven
  prescription **bandit is a real contribution**; proceed to the bandit-led paper.
- **NO (all arms ≈ Random or ≤ 0)** → sim cannot demonstrate the positive; the honest paper is
  **diagnostic-negatives + the generation-ceiling result + G1**.

Either outcome is publishable and answers "which framing works" — the point of the probe is to learn
this in ~2–3 days instead of after weeks of building a full bandit.

## 2. Why this is the crux (motivation)

The fixed-pool selection game is exhausted and retention-bound (trivial P(fail) beats every
sophisticated selector; offline AUC anti-correlates with deployed success; the saturation arm proved
the data to fix the hard region is **not in the pool**). The pivot is to prescribe **new** data — but
a stack scan (2026-07-17) shows the sim environment has **no autonomous way to manufacture successful
demos for the hard region**: on-demand MimicGen generation is not wired up, and the working
expert-rollout loop uses pi0/GR00T, which **share the weakness** (cross-policy universal failure).

This makes **learnability `p(1−p)`** — not raw `P(fail)` — the operative signal:
- `p≈0` (juice/jar): unlearnable → generation fails *and* selection saturates. `P(fail)`-top-K dumps
  the whole budget here. This is the coverage ceiling.
- `p≈mid` (colander/reamer ~0.45): the policy sometimes succeeds → GR00T can generate diverse
  successful demos → the **only** place with plausible headroom.
- `p≈1`: already solved, no headroom.

The bandit's only path to beating the trivial heuristic is **correctly avoiding the unfixable region**,
which `P(fail)` cannot do. The probe tests whether that headroom exists at all.

## 3. Fixed setup (reuse existing infra for comparability)

- **Student:** pi0 LoRA, robocasa-pretrained (`pi0_robocasa_pretrain_human300`, ~55% base).
- **Recipe:** identical to all prior arms — pi0 LoRA, **20k steps, batch 32**, same optimizer/seed —
  so only the data differs. Trustworthy net-Δ read requires the real recipe (do **not** reduce steps).
- **Smoke gate:** one **2k-step** LoRA fit on the Middle arm first, to confirm GR00T→LeRobot data
  trains cleanly (no format/action-space error) **before** committing the full runs.
- **Budget:** every arm = existing **400-demo base + K=20 new demos** for that arm. K=20 sits at the
  sweet spot of the measured dose-response (0→26.2%, ~14→35.1%, 200→37.1%, 610→29.9% on stratified
  targeted) and is cheap to generate.

## 4. Arms (difficulty bins)

Bins defined from the 500-scene weak-region baseline (per-category `p`). Final category membership to
be frozen from a single solid baseline estimate at planning time (per-category rates are noisy across
runs — e.g. juice 10–20%, reamer 53–65%).

| Arm | Bin (`p`) | Example categories | Role |
|---|---|---|---|
| **Hard** | 0–0.2 | jar, juice, cheese_grater, jug | **doubles as the `P(fail)`-top-K anchor** at K=20 → expect ≈0 net Δ |
| **Middle** | 0.35–0.55 | colander, pitcher, bottled_water, reamer | the headroom / learnability test |
| **Easy** | 0.6–0.7 | spray, yogurt | diminishing returns |
| **Random** | — | uniform over all 79 categories | the control every arm must beat |

*No separate 5th "trivial heuristic" arm is needed: the Hard arm IS `P(fail)`-top-K at K=20. The
existing core(200)/random stratified numbers (core 37.1%, random 35.1%, baseline 26.2%) are cited as
external reference points, not re-run.*

## 5. Collector — GR00T expert-rollout

1. Roll out **GR00T** (`groot_env`) on `PickPlaceCounterToSink`; keep only **successful** episodes.
2. **Rejection-sample** each episode to the arm's bin: constrain object category set and/or
   `--min_obj_height`/`--max_obj_height` (knobs already exist in `transfer/new_files/record_pi0_demos.py`).
3. Convert to LeRobot via `robocasa/scripts/dataset_scripts/convert_hdf5_lerobot.py`
   (`--camera_names robot0_agentview_left robot0_agentview_right robot0_eye_in_hand`, 256×256).
4. Recorded trajectories are **env-state + executed-action** (policy-agnostic) → valid pi0 training
   data even though generated by GR00T.

**Implementation dependency (verify in planning):** `record_pi0_demos.py` records *pi0* server
rollouts; a **GR00T analog** (`groot_env` rollout recorder) likely needs adapting. Confirm the
action/proprio conventions of GR00T-recorded demos match what the pi0 fine-tune expects (they should,
since both flow through the same robocasa env + `convert_hdf5_lerobot`).

## 6. Metrics & decision rule

For each arm, on the **powered stratified eval** (rollouts balanced across categories, seed batch
disjoint from training), report Δ vs the **base(400)-only** policy:
- **NET Δ overall** — the decider.
- **Targeted-region Δ** (the arm's own bin) and **Non-targeted (retention) Δ** — to see whether any
  targeted gain survives retention.

**Decision:**
- **Middle NET Δ > 0, and > Hard, and ≥ Random** → headroom + learnability signal → **build the bandit**.
- **All arms ≈ Random or ≤ 0** → no headroom → **diagnostic + generation-ceiling + G1** paper.

Arm granularity for a subsequent bandit is set from **where** the probe shows signal (finer bins if
Middle splits, coarser if not).

## 7. Honesty checks / confounds (these ARE results, not failures)

- **Retention trap:** an arm can lift its own region yet sink overall — *net*, not targeted, decides.
  This is the exact failure mode that killed value/coverage/whitening.
- **Uncollectable Hard bin:** GR00T shares the weakness, so it may not yield 20 successes for Hard —
  cap attempts and **report actual n collected**. "Even the stronger policy can't collect here" is the
  generation-ceiling result made concrete.
- **Self-distillation / no-new-info:** GR00T demos may not add information the base set lacks → part
  of what the probe measures. Rejection-sampling to under-covered configs is the mitigation.
- **Statistical power:** prior n=300 gave mostly within-noise gaps. **Lead with the ranking**
  (Middle > Hard > … ) at n≈300–400/arm; only power up (**n≥800**) the single decisive comparison
  (Middle vs Random) if the ranking looks right.

## 8. Cost & compute

- Generation: ~4–8 h total (Hard bin dominates via rejection sampling; Middle/Easy cheaper).
- Convert: ~10 min/arm.
- Fine-tune: 4 × 20k-step LoRA (~8 h each), parallelize 2-at-a-time on the 2×H100 → ~16 h wall.
- Eval: 4 arms × 300–800 rollouts × ~26 s, parallelizable.
- **Total ≈ 2–3 days wall.**

## 9. Validity criteria for the probe itself

The probe is only trustworthy if: (i) the 2k smoke confirms GR00T→LeRobot trains; (ii) all arms use
identical base + recipe + K, differing only in the 20 added demos; (iii) the eval seed batch is
disjoint from training and identical across arms; (iv) actual collected-n is reported per arm; (v) the
read is stated as ranking-first, with the decisive comparison optionally powered.
